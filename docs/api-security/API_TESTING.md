# API в Postman (ЛР4 п. 2)

Коллекция покрывает все варианты использования: вход по токену, справочники, счета, переводы,
историю, зарплату, роли менеджера и администратора, негативные проверки.

| Файл | Назначение |
|---|---|
| `docs/api-security/postman/FinanceSystem.postman_collection.json` | коллекция: 8 папок, 37 запросов, 57 проверок |
| `docs/api-security/postman/local.postman_environment.json` | окружение: `baseUrl = http://127.0.0.1:5005` |
| `docs/newman-report.json` | отчёт прогона коллекции (JSON, newman) |
| `tools/build_postman_collection.py` | скрипт, который собирает коллекцию и окружение |

## 1. Связывание запросов

Токен выдаёт `POST /api/v1/login`. Тест запроса сохраняет его в переменную коллекции
`clientToken`, `managerToken` или `adminToken`, а следующие запросы подставляют
`Authorization: Bearer {{clientToken}}`. Так же сохраняются и подставляются
`firstAccountId`, `secondAccountId`, `bankId`, `enterpriseId`, `pendingRequestId`,
`transferLogId`.

Важно: токены **не заданы в окружении** — пустое значение окружения перекрыло бы
переменную коллекции. В окружении только `baseUrl`.

## 2. Структура коллекции

| Папка | Запросы | Что проверяется |
|---|---|---|
| 01 Аутентификация | 3 | вход клиента (200), неверный пароль (401), текущий пользователь и роль |
| 02 Справочники | 2 | банки и предприятия непусты, их id сохраняются |
| 03 Счета | 6 | список, открытие вклада (201), свой счёт, чужой/несуществующий (404), неизвестный банк и тип (400) |
| 04 Переводы и история | 5 | перевод (200), нехватка средств (400), нечисловая сумма (400), тот же счёт (400), история с записью перевода |
| 05 Зарплата (клиент) | 4 | свои заявки, подача (201), повторная (400), выплата без подтверждения (403) |
| 06 Менеджер | 9 | вход, ожидающие клиенты, подтверждение, заявки, подтверждение с окладом, счета, блокировка, разблокировка, история клиента |
| 07 Администратор | 4 | вход, журнал, отмена перевода (200), повторная отмена (400) |
| 08 Негативные проверки | 4 | без токена (401), битый токен (401), несуществующая ручка (404 JSON), чужая роль (403) |

## 3. Запуск с отчётом

```bash
python seed.py                                   # демо-данные во временную БД
flask --app app run --port 5005                  # сервер, к которому идёт коллекция

newman run docs/api-security/postman/FinanceSystem.postman_collection.json \
       -e docs/api-security/postman/local.postman_environment.json \
       --reporters cli,json \
       --reporter-json-export docs/newman-report.json
```

Ту же коллекцию можно импортировать в Postman и запустить через Collection Runner.

## 5. Что коллекция даёт для защиты

- показывает, что API покрывает **все** варианты использования, а не только «пару ручек»;
- демонстрирует связывание запросов: без сохранённого токена следующие запросы вернули бы 401;
- в отчёте видны коды ответов и время — это же используется в ЛР5 как базовая линия нагрузки.
