# ЛР4 — вёрстка, API, безопасность, UI-автотесты

## Что требует задание (коротко)

1. **Вёрстка и совместимость:** целостность блоков, выравнивание, обтекание текста; адаптивность
   (ширина экрана и масштаб); интерактив (кликабельность, фокус, наведение, логотип → главная,
   favicon); реальные данные (длинные/короткие строки, пустые списки, много элементов); отсутствие
   404 и ошибок в консоли; **≥ 3 браузера** + мобильная эмуляция и таблица «проверка × браузер».
2. **API в Postman:** коллекция на все эндпоинты вариантов использования; позитивные и негативные
   запросы; связывание запросов (токен из логина дальше); запуск коллекции с отчётом.
3. **Безопасность:** доступ в закрытую зону без входа по прямому URL; подмена идентификатора (IDOR);
   ошибки не раскрывают стек, пути, SQL; логирование основных операций и ошибок.
4. **Автотесты UI:** Selenium/Playwright, паттерн Page Object, каждый тест создаёт свои данные,
   явные ожидания вместо пауз, при падении сохраняется скриншот.

## Что и как сделано

- **Адаптивность:** на экранах ≤ 720 px таблицы превращаются в карточки с подписями
  (`data-label` + CSS), горизонтальной прокрутки страницы нет — проверено на 390 px.
- **Интерактив:** favicon, логотип-ссылка на главную, `:focus-visible`, наведение, подтверждение
  опасных действий (`static/app.js`).
- **Кроссбраузерность:** одни и те же 15 проверок прогнаны в Chromium, Firefox и WebKit —
  везде ✅, консоль без ошибок (намеренные 403/404 не считаются).
- **Postman:** 37 запросов по всем вариантам использования; токен из логина сохраняется
  в переменную и подставляется дальше; негативные проверки — 401/403/404/400. Прогон newman:
  57 проверок, 0 провалов.
- **Безопасность:** IDOR закрыт на уровне сервиса (чужой счёт = «не найден»), ошибки без стека,
  входы и отказы пишутся в `logs/app.log`.
- **UI-тесты:** Page Object (`BasePage`, `LoginPage`, `AccountsPage`, `TransferPage`,
  `ManagerClientsPage`, `AdminLogsPage`), каждый тест создаёт свои данные, ожидания явные,
  при падении — скриншот `screenshots/FAILED-*.png`.

## Как показывать (10 минут)

1. Открыть приложение в браузере: главная, счета, мобильная ширина (сузить окно).
2. `COMPATIBILITY.md` — таблица «проверка × браузер», все ✅.
3. Postman/`API_TESTING.md`: показать login → token → запрос с токеном, затем негативный запрос.
4. `SECURITY.md`: строка про IDOR и ответ 404.
5. Запустить `pytest -m ui` — 15 тестов проходят в браузере.

## Вопросы и короткие ответы

**Что проверяют в вёрстке?** Целостность блоков, сетку, перенос длинного текста, отсутствие
горизонтальной прокрутки, кликабельность, фокус, favicon, пустые состояния.

**Зачем реальные данные?** На «Иванов Иван» всё красиво; длинное название банка или 50 счетов
ломает вёрстку — это и проверяем.

**401 vs 403?** 401 — не аутентифицирован (не вошёл), 403 — вошёл, но прав нет.

**400 vs 404?** 400 — запрос некорректный (плохие данные), 404 — ресурс не найден.

**Что такое IDOR?** Insecure Direct Object Reference: подмена id в запросе и доступ к чужому объекту.

**Почему ошибки не должны раскрывать стек и SQL?** Подсказывают злоумышленнику устройство системы.

**Зачем логировать?** Чтобы разобрать инцидент и доказать, кто что сделал.

**Page Object — что это?** Класс страницы с локаторами и действиями; тест не ищет элементы сам,
а вызывает методы страницы. Меняется вёрстка — правим один класс.

**Почему явные ожидания, а не паузы?** Паузы делают тесты медленными и нестабильными; ожидание
события — быстрым и надёжным.

**Что автоматизировать в первую очередь?** Частые регрессионные сценарии и проверки API;
редкие ручные кейсы выгоднее оставить людям.
