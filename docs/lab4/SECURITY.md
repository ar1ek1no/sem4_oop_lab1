# Проверки безопасности (ЛР4 п. 3)

Проверки выполнены скриптом `tools/security_check.py` на временной копии базы; он же формирует эту таблицу. Автоматические тесты, закрепляющие те же проверки: `tests/integration/test_api.py`, `tests/integration/test_errors.py`, `tests/integration/test_logging.py`, `tests/integration/test_client_web.py`.

## 1. Доступ в закрытую зону без авторизации

Анонимный запрос к любой странице каталога возвращает 302 на `/login?next=…`; сессия не создаётся, данные не отдаются. API отвечает 401 JSON.

## 2. Подмена идентификатора (IDOR)

Все операции с счётом идут через `AccountRepository.get_for_user(account_id, user_id)`. Чужой счёт для сервиса неотличим от несуществующего: ответ 404, данные не раскрываются, операция не выполняется. Тот же принцип в API и в формах страниц.

## 3. Сообщения об ошибках

Обработчики 400/401/403/404/405/500 отдают только текст для пользователя. Стек, пути файловой системы и SQL в ответ не попадают — проверяется поиском подстрок `Traceback`, `/mnt/`, `SELECT * FROM` в теле ответа.

## 4. Логирование

Каждое значимое действие пишется дважды: в журнал БД (`transaction_logs`, отмена опирается на `payload`) и в файл `logs/app.log` (входы, отказы, операции). Пароли и содержимое сессии в файл не попадают.
