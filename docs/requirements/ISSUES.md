# ISSUES — реестр дефектов

Основа для ВПО ЛР1 п. 3 («расхождения между требованиями и приложением регистрируются как дефекты»). Заполняется по мере проверки; формат полей — как требует задание: краткое описание, подробное (ожидаемый/фактический результат, ссылка на требование), шаги воспроизведения, воспроизводимость, важность и срочность, симптом, возможность обойти.

**Легенда важности:** критический / высокий / средний / низкий.
**Срочность:** немедленно / высокий / обычный / низкий.

## ISSUE-1. Пароли хранятся в открытом виде

**Краткое:** пароль пользователя сохраняется и сравнивается без хэширования.
**Ожидаемый результат:** в БД хранится необратимый хэш; сравнение — по хэшу (NFR-2).
**Фактический:** `models.py:18` — `password = Column(String)`; `services/auth_service.py:19` — `user.password == password`. В таблице `users` лежит читаемый пароль.
**Шаги:** открыть `finance.db` → `SELECT username, password FROM users;` → пароли читаемы; войти под любым пользователем, зная пароль из таблицы.
**Воспроизводимость:** 100 %.
**Важность:** критический. **Срочность:** высокий.
**Симптом:** утечка БД = утечка всех паролей.
**Обход:** нет; требуется исправление.
**Требование:** NFR-2.

**Ожидаемый результат:** регистрируется только клиент; менеджеры и администраторы создаются администратором или предзаполняются.
**Фактический:** `services/auth_service.py:8` — `register(username, password, role)`; форма (`ui/login_frame.py`) передаёт выбранную роль; проверка роли отсутствует.
**Шаги:** открыть окно входа → «регистрация» → выбрать роль `admin` → зарегистрироваться → подтвердить (или войти после подтверждения) → доступны функции администратора.
**Воспроизводимость:** 100 %.
**Важность:** критический. **Срочность:** немедленно.
**Симптом:** полный доступ к журналу и отмене действий у любого пользователя.
**Обход:** нет.
**Требование:** FR-1, FR-4.

## ISSUE-3. Перевод не проверяет владельца счёта (IDOR)

**Краткое:** списать средства можно с любого счёта, зная его `id`.
**Ожидаемый результат:** операция доступна только для счетов текущего пользователя; чужой `id` → отказ (NFR-5).
**Фактический:** `services/bank_service.py:16` — `transfer_money(from_id, to_id, amount)` проверяет блокировку и баланс, но не принадлежность `from_id` пользователю.
**Шаги:** войти клиентом A → выполнить перевод, указав `from_id` счёта клиента B → перевод проходит, баланс B уменьшается.
**Воспроизводимость:** 100 %.
**Важность:** критический. **Срочность:** немедленно.
**Симптом:** кража средств через подмену идентификатора.
**Обход:** нет.
**Требование:** NFR-5, FR-8.

**Шаги:** прочитать `undo_transaction`; попробовать добавить новую операцию — потребуется правка нескольких мест и знание «соглашений» по полям.

**Обход:** есть — осторожные правки.
**Требование:** ООП/SOLID (принцип открытости-закрытости).

## ISSUE-10. Тип счёта записывается подписью из формы, начисление процентов не работает

**Краткое:** при открытии счёта в БД попадает текст кнопки «счет?»/«вклад?» вместо типа `checking`/`saving`.
**Ожидаемый результат:** тип счёта — значение из фиксированного списка (`checking`/`saving`); начисление процентов находит вклады (FR-11).
**Фактический:** `ui/client_frame.py:39` — `values=["счет?", "вклад?"]`, выбранная строка уходит в `BankService.open_account`; `services/bank_service.py:63` фильтрует `acc_type == 'saving'`. В БД: счета 7–9 с `acc_type='счет?'/'вклад?'`, начисление на них не приходит.
**Шаги:** открыть клиентом вклад → «накопление (+5%)» → баланс вклада не изменился; `SELECT id, acc_type FROM accounts;` → «вклад?».
**Воспроизводимость:** 100 % для счетов, открытых через интерфейс.
**Важность:** высокий. **Срочность:** обычный.
**Симптом:** проценты по вкладу не начисляются, при этом отчёт «начислено 0 вкладов» выглядит успешным.
**Обход:** нет (только правка кода).
**Требование:** FR-6, FR-11.

**Шаги:** удалить все банки из БД → «открыть счёт» → приложение падает; ввести в сумму перевода текст → сообщение «проверьте корректность» без указания поля.
**Воспроизводимость:** 100 % при пустом справочнике.
**Важность:** средний. **Срочность:** обычный.
**Симптом:** непонятный отказ вместо диагностики.
**Обход:** частично — непустые справочники.
**Требование:** NFR-3.
